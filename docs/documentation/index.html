SuperSurf — Internal Documentation

A four-process MCP browser automation system. The headline trick: drive Chrome through a sideloaded extension instead of raw CDP, so the agent operates inside the user's real, lived-in browser profile while staying invisible to anti-bot systems that fingerprint Puppeteer and Playwright.

Reading order Start with System Architecture for the 30,000-foot view. Then dip into individual modules. The Trust Boundaries & Security page is the most important read for anyone touching browser_evaluate, secure_fill, audit logs, or the domain whitelist.

The four processes at a glance

AI Agent ──stdio (MCP)──▶ MCP Server ──Unix socket──▶ Daemon ──WS:5555──▶ Chrome Extension (multiplexes N sessions ↔ 1+ browser)
ProcessPackageRole
MCP Server supersurf-mcp One per AI client. Translates MCP tool calls into JSON-RPC and forwards them to the daemon. Hosts the audit logger, AST analyzer (secure_eval Layer 1), and tool dispatch.
Daemon supersurf-daemon Long-lived multiplexer. Owns the Chrome extension WebSocket(s), enforces tab ownership, schedules round-robin across sessions. Optionally manages multiple Chromium profiles.
Chrome Extension extension/ (CWS + sideload) MV3 service worker + content scripts. Performs DOM work in an isolated world undetectable by page JS. Hosts secure_eval Layer 2 (Proxy membrane) and the domain whitelist.
Shared shared/ (workspace-only) Zero-runtime-dep utilities (logger, types). Inlined into the published artifacts at build time.

Quick command reference

# Build everything
npm run build

# Dev server with hot reload
npm run dev.server

# Run all tests
npm run test

# Bump version across packages, commit
npm run version.bump patch

# Publish (npm + Chrome Web Store, owns git tagging)
npm run publish

# Daemon control
supersurf-daemon status [--verbose]
supersurf-daemon restart
supersurf-daemon observe   # tail the log

Where things live on disk

~/.supersurf/
├── daemon.pid                         # PID of the running daemon
├── daemon.sock                        # Unix socket — server↔daemon IPC
├── logs/
│   ├── daemon.log                     # always-on daemon log
│   ├── server.log                     # debug-mode only
│   └── sessions/
│       ├── supersurf-debug-*.log      # per-session debug logs
│       └── audit-*.ndjson             # ALWAYS-ON audit trail
├── extension/                         # cached extension (profiles experiment)
└── profiles/<name>/chrome-data/       # Chromium --user-data-dir per profile
